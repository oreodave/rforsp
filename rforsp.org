* PROJ IR compiler first pass :compiler:
** Preamble
We now want to make the program a compiler for the `rForsp` language.
Currently the program is a very simple interpreter: read -> compute ->
stop.  The AST that we read is basically 1-1 with what we evaluate,
which is nice for simplicity's sake, but isn't so nice for a genuine
compiler - the amount of nesting works directly counter to our ability
to optimise.

rForsp is, with the exclusion of environments, quite a flat language
itself:
- Bodies of code are implemented as flat buffers (vectors).
- nested function calls are simply adjacent words in the same vector
  i.e. ~f(g(h(x)))~ is ~[x h g f]~
- Operator precedence is a non-issue.

The pain points with compiling rForsp, which weren't painful when we
just concerned ourselves with interpreting, is that a lot of stuff is
implicit in its construction:
- ~1~ really represents "Push the integer 1 onto the value stack".
- ~$x~ means bind the symbol "x" in the current environment with
  whatever value is on the stack.
- ~f~ means lookup the symbol "f" in the current environment, then
  compute the result of it.

A flatter representation that makes these more explicit, in trade of
being more verbose, would allow us to reason about rForsp code more
effectively:
- Easier to evaluate since:
  - Each operation is explicit; we don't need to wait for the
    evaluator to figure it out when iterating but already have
    dedicated handles for each operation.
  - We're not jumping between different chunks of memory, but the same
    overall block.
- Easier to optimise, since we can perform static analysis on the code
  ahead of time.

The first attempt of the IR compiler will do the following passes:
- Convert source text to a High-Level IR (HIR) that preserves nesting,
  etc (analogous to the old interpreter homoiconic object model).
- Perform resolution and analysis to lower this HIR to a Semantic
  Stack-Effect oriented IR (SIR).
- Pass the SIR into a temporary evaluator.
